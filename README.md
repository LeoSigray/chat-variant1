# Клиент-серверный чат на C (вариант 1 — последнее сообщение пользователя)

Консольный чат на чистом C (C99) на TCP-сокетах. Сервер и клиенты могут
работать на разных компьютерах локальной сети. Код один для Windows (Winsock2)
и Linux/macOS (BSD-сокеты + pthreads).

| Файл | Назначение |
|------|------------|
| `server.c` | сервер: однопоточный, на `select()`, до 32 клиентов |
| `client.c` | клиент: главный поток читает клавиатуру, второй поток принимает сообщения |
| `common.h`, `common.c` | общий код: обёртки над сокетами, цветной вывод UTF-8 в консоль, проверка имён |
| `build.bat` | сборка под Windows (gcc из MSYS2/MinGW или MSVC) |
| `Makefile` | сборка под Linux/macOS (и MSYS2) |
| `CMakeLists.txt` | сборка через CMake / Visual Studio / CLion |

## Что умеет

* Сервер при подключении **приглашает клиента представиться** командой `#NewName <имя>`;
  той же командой имя можно **сменить во время работы**.
* Клиент **при запуске спрашивает имя**, а после приглашения сервера сам отправляет
  `#NewName <имя>`. Если имя занято или не подходит, клиент просит ввести другое.
* Имя — **одно слово**: буквы (только латиница или только кириллица — русский, украинский,
  белорусский алфавиты), цифры, `_ - .`, не длиннее 16 символов, хотя бы одна буква.
* **Два одинаковых имени не допускаются.** Имена сравниваются без учёта регистра
  (`Иван` = `иван`), а внешне неотличимые кириллица и латиница тоже считаются одинаковыми:
  нельзя занять `ВОВ` (кириллицей) рядом с `BOB` или `сосо` рядом с `coco`. Смешивать
  алфавиты в одном имени нельзя. Имя `Сервер` зарезервировано.
* Все сообщения подписаны именем отправителя:
  * обычное сообщение: `user: текст`
  * личное сообщение: `@user: текст` (клиент выводит его **ярко-малиновым цветом**)
  * служебные сообщения сервера начинаются с `[Сервер]` (бирюзовый цвет)
* **Вариант 1 — последнее сообщение пользователя:** сервер запоминает для каждого
  пользователя его последнее сообщение в общий чат, а любой участник может запросить его
  командой `#LastMsg <имя>`.

### Команды

| Команда | Действие |
|---------|----------|
| `#NewName <имя>` | задать или сменить имя |
| `#users` | список пользователей |
| `#ToUser <имя> <сообщение>` | личное сообщение пользователю |
| `#LastMsg <имя>` | **последнее сообщение пользователя** в общий чат (вариант 1); короткая форма — `#last <имя>` |
| `#help` | список команд |
| `#exit` | выйти из чата (или `#quit`; Ctrl+D в Linux/macOS, Ctrl+Z и Enter в Windows) |
| любой другой текст | сообщение всем участникам чата |

Регистр букв в командах не важен (`#users`, `#Users` и `#USERS` работают одинаково).
Строка, начинающаяся с `#`, но не являющаяся командой, не рассылается: отправитель получает
ответ «Неизвестная команда».

### Как работает `#LastMsg <имя>`

* Запоминается **последнее сообщение, отправленное в общий чат**. Личные сообщения
  (`#ToUser`) и команды не запоминаются: их содержимое видят только адресат и отправитель.
* В ответе сервер указывает автора и время отправки (по часам сервера):

  ```
  [Сервер] Последнее сообщение пользователя Мария (21:04:30): Всем привет!
  ```

* Имя в команде вводится без учёта регистра (`#lastmsg мария`). Можно запросить и своё
  собственное сообщение.
* Если пользователь ещё ничего не писал в общий чат — ответ
  `Пользователь Мария ещё ничего не писал в общий чат`.
* Если такого пользователя нет в чате (или он уже вышел) — `Пользователь «имя» не найден`.
  История вышедших пользователей не хранится.
* При смене имени (`#NewName`) сообщение сохраняется и запрашивается уже по новому имени.
* Сообщение запоминается, даже если кроме автора в чате никого не было.
* Команда доступна только после того, как клиент представился (как и общий чат).
* Если имя не указано или после него есть лишние слова, выводится подсказка о формате:
  `Формат команды: #LastMsg <имя>`.

## Сборка

### Windows

**MSYS2 / MinGW (gcc).** Добавьте `C:\msys64\ucrt64\bin` в `PATH` и запустите `build.bat`
(или вручную):

```bat
gcc -std=c99 -Wall -Wextra -O2 -o server.exe server.c common.c -lws2_32
gcc -std=c99 -Wall -Wextra -O2 -o client.exe client.c common.c -lws2_32
```

**Visual Studio.** Запустите `build.bat` из «Developer Command Prompt for VS» либо откройте
папку как CMake-проект. Если создаёте проект вручную, добавьте в него `server.c` + `common.c`
(или `client.c` + `common.c`) и **обязательно** включите ключ компилятора `/utf-8`
(Свойства проекта → C/C++ → Командная строка), иначе русские строки уйдут в сеть в cp1251.

Собранные программы рассчитаны на Windows 10 и новее (используют универсальную среду
выполнения UCRT; на Windows 7/8 нужно установленное обновление Universal CRT).

### Linux / macOS

```bash
make
```

или вручную:

```bash
gcc -std=c99 -Wall -Wextra -O2 -pthread -o server server.c common.c
gcc -std=c99 -Wall -Wextra -O2 -pthread -o client client.c common.c
```

## Запуск на двух компьютерах

1. **На компьютере-сервере** запустите сервер (порт по умолчанию 5555):

   ```
   server.exe            (Windows)
   ./server              (Linux/macOS)
   ./server 6000         (другой порт)
   ```

   Сервер выведет IP-адреса этого компьютера, по которым к нему можно подключиться.
   Узнать адрес можно и вручную: `ipconfig` (Windows) или `ip a` (Linux).

2. **Откройте порт в брандмауэре** на компьютере-сервере:
   * Windows: при первом запуске появится окно брандмауэра — нажмите «Разрешить доступ»
     для частных сетей. Либо выполните в консоли от имени администратора:

     ```bat
     netsh advfirewall firewall add rule name="Chat server" dir=in action=allow protocol=TCP localport=5555
     ```

   * Linux (ufw): `sudo ufw allow 5555/tcp`

3. **На компьютере-клиенте** запустите клиент, указав IP сервера:

   ```
   client.exe 192.168.1.10          (Windows)
   ./client 192.168.1.10 6000       (Linux/macOS, другой порт)
   ```

   Если IP не указан в командной строке, клиент спросит его после ввода имени —
   поэтому клиент можно запускать и двойным щелчком. В этом случае при ошибке
   (сервер недоступен, соединение разорвано) окно не закроется сразу, а покажет
   причину и попросит нажать Enter.

Оба компьютера должны быть в одной сети (или сервер должен быть доступен по
маршрутизации). Для проверки на одном компьютере можно указать адрес `127.0.0.1`.

## Пример сеанса

Клиент Ивана:

```
=== Клиент чата ===
Введите ваше имя для чата (одно слово): Иван
Подключение к 192.168.1.10:5555...
Соединение установлено.
[Сервер] Добро пожаловать в чат!
[Сервер] Представьтесь командой: #NewName <имя>
> #NewName Иван
[Сервер] Вы вошли в чат под именем Иван
...
[Сервер] К чату присоединился пользователь Мария
Мария: Всем привет!
@Мария: Иван, это личное сообщение        <- выделено цветом
#LastMsg Мария
[Сервер] Последнее сообщение пользователя Мария (21:04:30): Всем привет!
#users
[Сервер] Пользователи в чате (2):
   1. Иван  (это вы)
   2. Мария
```

Обратите внимание: личное сообщение Марии не стало её «последним сообщением» —
запоминаются только сообщения в общий чат.

Журнал сервера (адреса клиентов выводятся только здесь, на консоли сервера):

```
[21:04:05] Новое подключение: 192.168.1.20:50712 (всего клиентов: 1)
[21:04:07] 192.168.1.20:50712 представился как «Иван»
[21:04:30] Мария: Всем привет!
[21:04:41] Личное сообщение: Мария -> Иван
```

## Протокол (для отчёта)

* TCP, текстовые строки в UTF-8, каждая заканчивается символом `\n`.
* Клиент → сервер: команда (`#NewName`, `#users`, `#ToUser`, `#LastMsg`, `#help`, `#exit`)
  или текст сообщения. Максимальная длина строки — 1024 байта.
* Сервер → клиент:
  * `имя: текст` — обычное сообщение;
  * `@имя: текст` — личное сообщение;
  * `[Сервер] ...` — служебное сообщение, строки-продолжения начинаются с двух пробелов.
    Ответ на `#LastMsg` — служебное сообщение
    `[Сервер] Последнее сообщение пользователя <имя> (<ЧЧ:ММ:СС>): <текст>`.
* Порядок входа: сервер присылает приветствие и приглашение
  `[Сервер] Представьтесь командой: #NewName <имя>` → клиент отвечает `#NewName <имя>` →
  сервер отвечает `[Сервер] Вы вошли в чат под именем ...` или `[Сервер] Имя не принято: <причина>`.
* Данные для варианта 1 хранятся на сервере в структуре клиента (`last_msg`, `last_msg_at`,
  `has_last_msg` в `server.c`): при каждом обычном сообщении запись перезаписывается,
  при отключении клиента вместе с ним исчезает.
* Сервер собирает строки из TCP-потока (данные могут прийти частями или слитно),
  удаляет управляющие символы и некорректный UTF-8, поэтому один клиент не может
  «сломать» терминал другим.
* Сервер однопоточный: `select()` следит за слушающим сокетом и всеми клиентами.
  Сокеты клиентов неблокирующие: клиент, который перестал принимать данные, отключается
  и не может «подвесить» чат для остальных.
* Защита от флуда: у каждого клиента есть «бюджет» 4 КБ/с (кратковременно — до 16 КБ,
  этого хватает на вставку большого текста), и каждая строка дополнительно «стоит» 256 байт,
  потому что её рассылают всем. Для обычных сообщений это порядка десяти сообщений в секунду
  в среднем (для односимвольных — до 40). Пока бюджет исчерпан, сервер просто не читает
  сокет этого клиента, и TCP сам притормаживает отправителя.
* TCP keepalive: если компьютер клиента (или сервера) внезапно пропал из сети, соединение
  будет закрыто примерно через 30–45 секунд, а имя освободится.
* Подключение, которое не представилось за 120 секунд, закрывается.
* Если сервер переполнен (32 клиента), новый клиент получает сообщение
  `[Сервер] Сервер переполнен, попробуйте подключиться позже`.
* Ctrl+C корректно останавливает сервер с уведомлением клиентов. Режим выделения мышью
  (QuickEdit) в окне сервера отключён: в консоли Windows он приостанавливает вывод, а
  однопоточный сервер вместе с ним остановил бы весь чат.
